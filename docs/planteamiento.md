# Scope and integration contract

Updated: October 6, 2026.

## Confirmed deliverable

This project delivers api.php, download.php, and common.php for the existing SQLupdate hosting directory. The original documents in F:\SQL_Update describe client-specific directories, versioned ZIP packages, HTTPS, and BasicAuth. The guide contains both a statement that endpoints are already prepared and instructions to place endpoint files. The user's subsequent clarification establishes that creating those endpoints is our responsibility.

The initial C# implementation has been removed at the user's request. Tytan integrates these HTTP endpoints into its own application.

## Responsibilities

| Owner | Responsibility |
| --- | --- |
| This PHP server | Authenticate, validate requests, list folders/ZIP metadata, stream selected ZIPs |
| Hosting administrator | PHP execution, HTTPS, BasicAuth, permissions, package publication, logs |
| Tytan application | Know the client folder, product, and installed version; compare versions; download and validate; install and record the installed version |

The PHP API does not receive an installed version and does not choose or install updates. This is the implemented listing/download contract.

## Endpoint contract

GET or HEAD api.php lists the update root. The optional dir parameter selects a relative client directory. GET or HEAD download.php requires a file parameter containing a relative ZIP path from the listing. Requests use HTTPS and BasicAuth.

Successful listing responses are arrays with name, type, size, modified, and path. type is folder or file; folder size is null; file size is bytes; modified is UTC. An empty folder returns []. Download responses contain the ZIP bytes and attachment headers. Errors generated by PHP use an error field and an appropriate HTTP status.

## Version handling in Tytan

Packages follow the documented convention Product_XXX.XXX.XXX.zip, for example Faktury_008.000.043.zip. The application filters packages by product and compares the three numeric components against its installed version. Products FK2025, FK2026, and Faktury are handled separately. Modification timestamps are metadata, not version precedence.

Example: Faktury installed at 008.000.042 should download 008.000.043; an installed version equal to or higher than 008.000.043 should not download that package. These are client integration rules, not PHP endpoint behavior.
